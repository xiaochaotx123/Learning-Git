#### 版本库
版本库又名仓库（Repository）可以简单理解成一个目录，这个目录里面的所有文件都可以被Git管理起来，每个文件的修改、删除，Git都能跟踪，以便任何时刻都可以追踪历史，或者在将来某个时刻可以“还原”。

#### $ 
$ 叫做命令提示符。它表示"电脑准备好了，请输入指令"。

#### mkdir 
mkdir是 Make Directory的缩写，表示创建一个空目录。创建空目录的地方取决于敲mkdir命令时终端停留的位置
- 空格问题：如果写命令 mkdir My Test，系统会以为要创建两个文件夹，一个叫My，一个叫Test。如果要创建带有空格的名字，必须加上引号：mkdir "My Test"。但强烈建议以后写代码永远不要永远不要用空格命名文件夹，用My_Test或者myTest代替。
- 大小写敏感：Git Bash里严格区分大小写，Test和test是两个不同的文件夹。

### cd

#### cd 
cd是Change Directory（改变目录）的缩写，它的作用是去"去某个地方"
cd 和 cd ~ 是同一个命令，都表示回到 当前用户的主目录

#### cd ~ 
在命令行中，~ （波浪号）专门用来代表"当前用户的主目录（Home Directory）"
所以：
- 输入 cd（后面什么都不加）回车，终端就会带你回到主目录
- 输入 cd ~ 回车，效果一模一样，也是回到主目录
- 输入 cd ~/Learning-Git，就是回到主目录下的 Learning-Git 文件夹。

#### cd .. 
.. 表示上一级目录，所以 cd .. 表示回到上一级目录

#### cd - 
cd - 命令表示退回到上一次待过的地方（历史目录）。假设你先去了 A 文件夹，又去了 B 文件夹。这时候敲 cd -，它会直接带你回到 A 文件夹。再敲一次，又把你送回 B 文件夹。


#### pwd 
pwd 是 Pring Working Directory（打印工作目录）。pwd 就是你在命令行里的“GPS定位”或“看门牌号”。 你敲下它，电脑就会告诉你：“你现在正站在哪个文件夹里。”

#### explorer .
explorer . 是 Windows 下用文件资源管理器打开当前目录 的命令。
- explorer：调用 Windows 的资源管理器程序 explorer.exe
- .：表示“当前目录”
所以explorer . 就是：在当前命令行所在文件夹弹出一个文件资源管理器窗口
explorer .. 就是打开上一级目录


#### ls -ah
ls -ah 命令是列出当前目录下的所有文件
- ls：list（列表）的缩写
- -a：All（所有）的缩写。这是重点！ 在 Linux 系统中，以 . 开头的文件默认是隐藏的，普通的 ls 看不到它们。加了 -a，就能把所有隐藏文件也显示出来。
- -h：Human-readable（人类可读）的缩写。让文件大小以 KB、MB 这种我们能看懂的格式显示，而不是一堆长长的字节数字（通常和 -l 搭配使用）。
ls -ah 就是：“把当前文件夹里所有文件（包括隐藏的），以人类能看懂的方式列出来。

#### .git文件
上面说的列出隐藏的文件就是这个 .git文件  
因为 .git 文件夹的名字是以英文句点 . 开头的。在 Linux、Mac 以及 Windows 的 Git 工具中，以 . 开头的文件/文件夹默认被视为“隐藏文件”。  
千万、千万、千万不要手动打开、修改或删除 .git 文件夹里的任何东西！它是 Git 的“大脑”，里面记录了你所有的提交历史、分支、配置信息。如果你手动删了它，你的本地仓库就会瞬间失去所有的历史记录，变成一个普通的空文件夹。  


#### 一般的操作：
```python
git status
git add .
git status
git commit -m "备注"
git push
```
- git status（第一次）  
查看当前工作区的状态：哪些文件被修改了、哪些是新增未跟踪的、哪些已经在暂存区。  
作用：提交前先确认改动范围，避免把临时文件、测试文件误提交。
- git add .  
将当前目录下所有改动（包括修改的文件、新增的文件）全部添加到暂存区。  
注意：`.` 代表当前目录，只会添加当前目录及子目录下的改动，不会包含上级目录。  
- git status（第二次）  
校验 `add` 的结果：确认暂存区里的文件是不是你本次想要提交的内容，有没有漏加、多加。  
把暂存区的所有改动正式提交到本地版本库，生成一条带唯一标识的永久版本记录。  
- git commit -m "备注"  
把暂存区的所有改动正式提交到本地版本库，生成一条带唯一标识的永久版本记录。  
- git push  
将本地仓库的新提交推送到远程仓库（GitHub / Gitee / 公司 Git 服务等），完成云端同步。  


### git restore  
#### 场景一  
你只是不想提交了，但文件里写的内容还要留着继续改，**只把它们从暂存区拿出来**，这是 `git add .` 对应的反向操作。  
撤销所有暂存的文件（对应 `git add .` 的逆操作）  
```python
git restore --staged .
```
- 撤销单个指定文件  
```python
git restore --staged 文件名  
```
执行后，文件会回到「已修改但未暂存」的状态，你写的内容完全不会丢失，只是移出了暂存区。  

#### 场景二  
如果你连文件里的修改都不想要了，直接恢复到上次提交时的原样：  
还原所有修改的文件：
```python
git restore .
```
还原单个文件  ·
```python
git restore 文件  
```
这个操作会直接丢弃你所有未提交的修改，无法恢复，执行前请确认清楚。
