#### 集中式版本控制系统
集中式版本控制系统（Centralized Version Control System，CVCS） 是一种采用“客户端—服务器”模型的版本控制方式。
- 中央服务器保存完整版本库：所有文件的历史版本、分支、标签等都在中央仓库中。
- 客户端只保存工作副本：开发者从服务器“检出”最新版本，修改后“提交”回服务器。
- 提交、更新通常必须联网：因为版本历史集中在服务器，离线时一般只能编辑和查看本地副本，不能正式提交。
- 权限集中管理：管理员可在中央服务器统一控制谁可读、可写、可提交。
- 版本历史线性、集中：版本号通常由服务器统一分配。

#### 分布式本本控制系统
分布式版本控制系统（Distributed Version Control System，DVCS）每个开发者本地都有一份完整的仓库副本，不仅包含当前文件，还包含全部历史版本、分支、标签等。你可以把它理解成：人人都有一整个“中央仓库”的拷贝。
- 本地有完整历史：查看日志、比较版本、创建分支、提交，大多可离线完成。
- 提交先在本地进行：修改后先提交到本地仓库，再通过网络同步到远程仓库。
- 没有唯一中央权威：技术上每个副本都是完整仓库；但团队通常会约定一个远程仓库（如 GitHub、GitLab）作为协作中心。
- 同步靠推送/拉取：push 把本地提交传到远程，pull/fetch 把别人的提交取回本地。
- 分支和合并能力强：创建分支成本低，适合并行开发、功能分支、Pull Request 流程。
